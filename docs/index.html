    Get started / 02

    A briefing in one command

    By default, the CLI creates an English PowerPoint with English speaker notes. The newest matching articles in the selected period are processed first.

    English presentation
    copilot-changelog --from 2026-08-01 --to 2026-08-31

    Italian slides, bilingual notes, and a website

    Works in PowerShell, Bash, and Zsh
    copilot-changelog --from 2026-08-01 --to 2026-08-31 --slides-language it --speaker-notes-languages en,it --website

    Try a smaller selection

    Five newest matching entries
    copilot-changelog --from 2026-08-01 --to 2026-08-31 --limit 5 --output output-demo

    Every invocation prints the installed version and performs a short release check. Interactive terminals show a Copilot-themed banner; NO_COLOR disables color. Redirected output stays script-friendly, with progress on stderr and generated file paths on stdout.

    The startup release check has a three-second deadline, including the response body. A failed check does not prevent generation.

    Guides / Collection

    Two sources. One selection.

    The default collector combines the GitHub Copilot changelog with every AI & ML GitHub Blog article in the date range. It does not limit blog articles to titles containing “Copilot.”

    1. Discover. Query each historical month with opened-months=MM-YYYY and paginate the blog API.
    2. Select. Merge sources, deduplicate URLs, sort newest-first, then apply the global --limit.
    3. Prepare. Download all selected source articles before starting AI enrichment. Unreadable or empty selected content stops the run with a diagnostic.

    Five continuously replenished download slots prepare source pages. News indexes are cached for five minutes and article pages for 24 hours under copilot-changelog-cli/news-v1 in the operating system's temporary directory. Fresh cache entries avoid repeat downloads; invalid cache records are refreshed.

    Use a custom feed

    --feed replaces both default sources with an RSS URL or local XML file. Feed entries are date-filtered and URL-deduplicated; selected entries must contain readable article text.

    Deterministic repository fixture
    npm run dev -- --from 2026-08-01 --to 2026-08-31 --feed test/fixtures/feed.xml --no-ai

    Guides / Output design

    Structured for the audience

    A deck contains an opening slide, section dividers, and a visual title plus a detail slide for each accepted article. Images preserve their aspect ratio. Source links, publication dates, the Copilot mark, and localized speaker notes keep the briefing grounded.

    Section-specific detail cards
    SectionWhen it appliesCards
    ModelsNewly available models, not settings, policies, pricing, or model pickers.Model name · Availability · Key capabilities · When to use / avoid
    Enterprise AdminsEnterprise owner/admin settings in the GitHub web portal or management console. Generic member features and API/CLI-only administration stay in their topic section.Announcement · Availability · Impact · Audience
    AnnouncementsBroader product, workflow, and adoption changes.Announcement · Availability · Impact · Audience
    IDEChanges in supported editors.Feature · Availability · Key capabilities · How to use
    RetirementsDeprecations, removals, and migrations.Subject · Retirement date · Reasons · Replacement

    Models, IDE, and Retirements use equal-width cards. Announcements and Enterprise Admins give the main explanation and impact cards a wider left column, with availability and audience on the right.

    Content budgets

    • Summary: one complete sentence, at most 32 words / 220 characters, leading with the product or capability.
    • Notes: 2–4 standalone bullets, each at most 16 words / 110 characters.
    • Explanatory cards: target 28–34 words; at most 36 words / 250 characters for capabilities, usage guidance, reasons, and replacement.
    • Wide announcement/impact cards: up to 44 words / 300 characters. Announcement prompts target 30–40 words.
    • Compact labels: up to 18 words / 130 characters. Availability, retirement date, and audience use up to 26 words / 170 characters.
    • Speaker notes: an 80–140 word presenter script for every requested language on AI-enriched article slides.

    Each card should contribute a distinct fact: a concrete change, mechanism, practical effect, action, or essential qualifier. Short sources are not padded with invented information. Up to three semicolon-separated points are allowed; commas inside model names or qualifiers do not count as separate points.

    Guides / AI quality

    Review that tells the model what failed

    The source determines the required section. Copilot receives the article and section-specific instructions, with examples encouraging concrete explanations rather than vague benefit statements.

    1. Generate and validate. The initial response is checked for structure, required fields, presentation limits, and requested notes.
    2. Correct with feedback. Up to three corrective rewrites receive the exact validation errors. Prompts preserve valid fields, exceptions, eligibility, deadlines, and prerequisites.
    3. Request a final review. After four invalid enrichment attempts, a separate tool-disabled reviewer receives the rejected response, validator errors, and original source-grounded task.
    4. Continue when content is still invalid. Omit the article's slides with a warning, process later articles, and keep accepted work in the checkpoint for resume.
    No mechanical trimming

    AI-generated fields are rewritten, not truncated, and extra bullets are not silently dropped. The model is asked to remove repetition before removing source-backed explanations.

    Transient SDK failures share the bounded attempt budget. Timeouts are not retried automatically. Empty primary or reviewer responses, service failures, and trace-write errors remain explicit failures rather than being treated as content-review rejections.

    These checks validate presentation content and formatting; they are not an independent factual audit. Review generated slides before sharing them with an audience.

    Guides / Files & diagnostics

    Know what gets written

    Example output directory
    output/
  copilot-changelog-2026-08-01-to-2026-08-31.pptx
  copilot-changelog-2026-08-01-to-2026-08-31.trace.jsonl
  copilot-changelog-2026-08-01-to-2026-08-31.html  # with --website

    Different date ranges have different filenames. Re-running the same range rewrites its deck and requested website; choose another --output directory to preserve an earlier version.

    The optional website embeds article images and provides local search. It is a generated digest, separate from this GitHub Pages documentation site. Slide and note languages are independently selectable; the digest's interface labels remain English.

    Trace logs

    The JSONL trace is appended on each run with a unique runId. It records source preparation, prompts, raw AI responses, validation, checkpoint activity, skipped articles, and failures. Its path is printed at startup and included in error messages.

    Mirror trace events to stderr
    copilot-changelog --from 2026-08-01 --to 2026-08-31 --verbose
    Review logs before sharing

    Trace files and verbose terminal output include source excerpts, full prompts, and generated text. Without --verbose, the trace file is still written.

    Guides / Recovery

    Continue, don't start over

    A hidden checkpoint is saved after each successfully enriched article. If a slide still fails review, later articles continue and the CLI writes a partial deck. The rejected article remains pending.

    Retry pending articles with the same configuration
    copilot-changelog --from 2026-08-01 --to 2026-08-31 --resume

    Resume reuses accepted articles, retries missing ones, and rewrites the deck with recovered slides. Add --website again if you also want to update the digest. The checkpoint is removed only after all selected articles complete and every requested output is written.

    Interactive versus automated runs

    An interactive terminal asks Previous run found (7/12 entries completed). Resume or restart? [R/s]:. Enter or R resumes; S discards the checkpoint. Scripts and CI must explicitly choose --resume or --restart.

    Discard progress and regenerate all selected content
    copilot-changelog --from 2026-08-01 --to 2026-08-31 --restart

    Compatibility and locks

    • Checkpoints match selected article URLs, model, AI mode, languages, and content format version. An incompatible checkpoint is discarded with a message.
    • Changing concurrency or request timeout does not invalidate a compatible checkpoint. Layout changes can reuse accepted text; use restart to request new AI text.
    • Malformed checkpoints are preserved and reported on resume. Restart discards them without parsing.
    • A per-deck .lock blocks competing processes for the same output directory and date range. Restart does not override an active lock.
    After a forced termination

    Confirm that no run is still active, remove only the reported stale lock, and resume. Do not delete the checkpoint. Locks are released automatically after normal completion or handled errors.

    Reference / Runtime

    Predictable work, bounded waits

    Sequential enrichment is the default: one shared client, one fresh session per article. Use --concurrency 2 through 8 only when your Copilot environment supports the load. Corrective prompts stay associated with their source; results retain changelog order within each section.

    The 180-second deadline applies separately to each response, runtime startup, model discovery, and primary or reviewer session creation. Timeouts stop new articles and retries. Active peers may complete and be checkpointed before runtime shutdown.

    Resume with less contention
    copilot-changelog --from 2026-08-01 --to 2026-08-31 --resume --concurrency 1 --request-timeout 180

    Increasing the timeout permits slower responses; it does not speed up inference. Abort/disconnect and shutdown have bounded cleanup waits. Both sessions are cleaned up even if one cleanup fails, and cleanup diagnostics are reported alongside the original error. A forced SDK stop is attempted if graceful shutdown fails.

    Source downloads remain parallel. Help and version commands avoid loading generation dependencies, and the SDK is imported only when AI is needed. Sessions have no tools available because the source is supplied. PowerPoint theme changes happen in memory before the final write.

    Reference / Maintenance

    Keep the CLI current

    Check, then update
    copilot-changelog --version
copilot-changelog update --check
copilot-changelog update

    Updates require a published GitHub release. Release lookup allows 30 seconds; each asset download allows five minutes. Downloaded release assets are verified against SHA256SUMS.

    • npm: installs the new version with npm install --global; that version must also be published to npm.
    • Windows setup: launches the new installer after the current process exits.
    • Debian / macOS packages: invoke sudo dpkg -i or sudo installer; administrator credentials may be required.
    • Portable: stages and replaces the managed application, runtime, launcher, and README after exit. Old dependency directories are not merged. Rollback restores the previous files after a failed replacement; user output outside managed paths is preserved.

    Close other running copies first. Inspect .copilot-changelog-update.log in the installation directory for the result. Competing updaters are blocked by .copilot-changelog-update.lock.

    Interrupted portable update

    Confirm that no updater is active. Inspect the logged backup location and restore retained managed files if needed before removing the stale update lock. Do not delete recovery backups blindly.

    Reference / Help

    When a run needs attention

    A slide was omitted after review

    The remaining accepted content is still written. Re-run the same dates, model, feed selection, and language settings with --resume. The rejected article is retried; accepted text is reused.

    Authentication, model, or request failure

    Verify Copilot access and authentication. Check the reported model availability, reduce concurrency to 1, and resume. Changing the model makes the existing checkpoint incompatible; keep it unchanged if you need to preserve completed AI work.

    Source preparation failed

    Every selected article must be readable before enrichment starts. Check the URL, feed content, and internet connection. Downloaded articles remain cached. If the diagnostic identifies an unreadable cache directory, repair its permissions or remove that specific cache after reviewing the error.

    A run lock or damaged checkpoint remains

    For a lock, confirm the original process has stopped before removing only the reported lock file. A damaged checkpoint is preserved on resume; --restart discards it. Neither option bypasses an active run lock.

    The CLI is not found on Windows

    Open a new terminal after installing so the updated PATH is loaded. For a portable package, invoke the launcher from its extracted directory or add that directory to PATH.

    Badges, documentation, or download links return 404

    The repository must be accessible and pushed, workflows must have run, and downloads require a release. Enable GitHub Pages with GitHub Actions as its source. See the publishing checklist; local files alone do not create a public site.

    Trace or output writing failed

    Check directory permissions, available disk space, and whether the presentation is open in another application. Fix the filesystem problem and resume. Do not share the trace without reviewing its prompts and source content.

    Build & publish / Distribution

    Package the tested dependency tree

    Platform packages contain the application, production dependencies, and a bundled Node.js runtime. Scripts copy the manifest and lockfile into staging and run npm ci --omit=dev. Windows and Unix packages smoke-test the runtime, launcher, and SDK.

    npm pack bundles the validated presentation dependency subtree so npm consumers receive the patched image parser. Prepack adjusts that bundled manifest; postpack restores the original installed manifest. Run npm ci before packing. If interrupted after preparation, run npm run postpack before retrying.

    Windows x64

    Requires Inno Setup 6. The multi-resolution Copilot icon (16–256 pixels) is embedded in the launcher and installer, and used by shortcuts and the installed-app entry.

    PowerShell
    winget install --id JRSoftware.InnoSetup --exact
npm run build:windows

    Use npm run build:portable for just the portable package. npm run build:installer is an alias for the installer build.

    Linux

    Requires curl, tar, and dpkg-deb. Run the command matching your native Node.js architecture.

    On a matching Linux runner
    npm run build:linux -- x64
# On an ARM64 runner instead:
npm run build:linux -- arm64

    Requires the built-in pkgbuild. Unix packaging rejects cross-platform and cross-architecture builds before staging dependencies.

    Build & publish / Automation

    From a tag to a release

    • ci.yml runs type-checks and tests on Windows, Linux, and macOS, including the minimum supported Node version.
    • pages.yml publishes this documentation independently of application releases.
    • release.yml validates the version, builds native platform packages, generates SHA256SUMS, and publishes only after validation succeeds.

    Update the version in the manifest and lockfile, commit, then push a matching version tag. For example, if the package version is 1.0.0:

    Publish a matching tag
    git tag v1.0.0
git push origin v1.0.0

    The tag must equal v followed by the package version. Workflow dispatch can build packages without publishing a tag release. Publishing to npm is a separate operation; the release workflow does not run npm publish.

    Build & publish / This site

    Publish on GitHub Pages

    The repository already includes a GitHub Actions deployment workflow. No paid hosting, site generator, or additional runtime is required for this static site; GitHub Pages availability depends on your repository visibility and plan.

    1. Connect the repository. Create or select your GitHub repository, configure its origin, and push the source to main.
    2. Enable Pages. Open Settings → Pages → Build and deployment and choose GitHub Actions as the source. Ensure repository Actions are enabled.
    3. Deploy. Push a change under docs/, or open Actions → Deploy documentation → Run workflow on main.
    4. Verify. Wait for the deployment to succeed, then open the URL in the github-pages environment. No release tag is needed.
    Configured site address

    https://congiuluc.github.io/GitHub-Updates-CLI/

    The address will return 404 until the repository is accessible and the first deployment succeeds. The README status badges also need their workflows to run.

    Using a different repository name or owner

    Update repository, homepage, and bug-report metadata in package.json; the repository constant in src/updater.ts; and repository/site URLs in the README and documentation. This site's stylesheet, script, images, and section links are relative, so it works beneath a project Pages subpath.

    This website is documentation for the CLI. It is not the optional article digest created by --website, and deploying it does not publish a CLI release.

    Build & publish / Trust

    Share deliberately

    Downloaded article images must be PNG, JPEG, or GIF, pass signature checks, and remain below the configured size limit. The transitive image-size dependency is overridden to patched version 2.0.4 while the presentation library requests its older 1.x line.

    Keep tokens and signing credentials out of source control. Use encrypted GitHub Actions secrets for releases. Review generated content and trace logs before distributing them.

    Package signing

    Automation currently produces unsigned packages, which can trigger operating-system warnings. Before signed public distribution, configure:

    • An Authenticode certificate for Windows.
    • A Developer ID Installer certificate and notarization for macOS.
    • Repository signing for a published Debian package repository.

    GitHub and Copilot names and marks identify the source service and generated changelog content. This project is not an official GitHub product.
