    Get started / 01

    Install your way

    Release packages include Node.js. For source and npm installations, use Node.js 24 LTS, version 24.21.0 or newer within 24.x. Other major versions are not supported. CI and bundled runtimes use the version pinned in .node-version.

    Download a published release ↗

    Current source versus installed releases

    This guide describes the current source. Published packages may not yet contain every option shown here. Run copilot-changelog --help to inspect your installed CLI, or build from a local checkout for newer features. A documentation deployment does not publish or update the CLI.

    From npm

    After the package is published
    npm install --global copilot-changelog-cli
copilot-changelog --help

    From a local checkout

    Run in the repository root
    npm ci
npm run build
npm install --global .

    On Windows, open a new terminal after installation if the command is not on PATH. Windows binaries, the installer, the Start Menu shortcut, and the installed-app entry use the Copilot icon. Terminal-tab icons are controlled by the terminal profile.

    Authenticate for AI enrichment

    You need an account with access to GitHub Copilot and an authenticated Copilot CLI/SDK environment. Launch the GitHub Copilot CLI with copilot, then enter /login inside its interactive session and follow the sign-in instructions.

    Use the installed dependency from a source checkout
    npx --no-install copilot
# Inside the Copilot session, enter /login

    For automation, the runtime also accepts a fine-grained token with the Copilot Requests permission through GH_TOKEN or GITHUB_TOKEN. Keep tokens in your environment or secret store, never in source files. GitHub CLI authentication alone is not a substitute for verifying Copilot access.

    -A, --no-ai uses deterministic templates for testing; it does not generate AI-edited content. This is independent of -a, --include-ai-ml, which selects a news source. See troubleshooting if your selected model is unavailable.

    Get started / 02

    A briefing in one command

    By default, the CLI creates an English PowerPoint with English speaker notes. The newest matching articles in the selected period are processed first.

    English presentation
    copilot-changelog --from 2026-08-01 --to 2026-08-31

    Examples use long options for clarity. Case-sensitive short aliases remain supported; see the complete option reference.

    Any locale, multilingual notes, and a website

    Works in PowerShell, Bash, and Zsh
    copilot-changelog --from 2026-08-01 --to 2026-08-31 --slides-language fr-CA --speaker-notes-languages fr-CA,ja,ar --website

    Languages accept BCP 47 locale tags recognized by the runtime, not an English/Italian allowlist. Examples include de, pt-BR, zh-Hant, sr-Latn-RS and ar. Tags are canonicalized, so FR-ca becomes fr-CA; duplicate note locales are removed. Use hyphens rather than underscores. Invalid tags fail before source collection.

    AI localizes article text, slide headings, section/card labels and introductory presenter notes. Dates use the requested locale, right-to-left slide text is supported, and introductory notes are kept in each requested note locale. Translated deck text is saved in the content JSON and cache for offline rendering. Translation quality and font coverage depend on the model and presentation viewer. Source quotations remain verbatim in their original language.

    --no-ai is a deterministic test mode, not a translation engine. It retains source text and uses built-in English/Italian template text or a warned English fallback for other locales. The optional website retains its English interface while marking article content with its selected locale and text direction.

    Try a smaller selection

    Five newest matching entries
    copilot-changelog --from 2026-08-01 --to 2026-08-31 --limit 5 --output output-demo

    Generation commands print the installed version and perform a short release check. Interactive terminals use cyan for information, green for success, yellow for warnings/retries, red for failures and dim text for trace paths. Messages retain their descriptive text, so color is never the only signal. NO_COLOR disables colors; redirected output and TERM=dumb stay plain. Progress and the final human-readable summary go to stderr; generated file-path records remain on stdout.

    The startup release check has a three-second deadline, including the response body. A failed check does not prevent generation.

    Guides / Collection

    Your sources. One selection.

    By default, the collector uses only the GitHub Copilot changelog. GitHub Blog AI & ML articles are disabled by default; add --include-ai-ml to include them. Use --rss to add one or more RSS URLs or local XML files. Added feeds and the optional blog include every in-range article, not only titles containing “Copilot.”

    1. Discover. Query each historical changelog month with opened-months=MM-YYYY, read configured RSS feeds, and paginate the blog API only when opted in.
    2. Select. Merge sources, deduplicate URLs, sort newest-first, then apply the global --limit.
    3. Prepare. Download selected changelog and blog pages and validate selected RSS content before starting AI enrichment. Unreadable or empty selected content stops the run with a diagnostic; a failed feed is never silently ignored.

    Five continuously replenished download slots prepare source pages. News indexes are cached for five minutes and article pages for 24 hours under copilot-changelog-cli/news-v1 in the operating system's temporary directory. Fresh cache entries avoid repeat downloads; invalid cache records are refreshed.

    Add RSS feeds or opt into the blog

    Add sources to the changelog
    copilot-changelog --rss https://example.com/news.xml https://example.org/releases.xml
# Repeated options and local XML files work too:
copilot-changelog --rss https://example.com/news.xml --rss team-news.xml --include-ai-ml

    Replace the example URLs with real RSS endpoints. Quote paths containing spaces, for example --rss "team news.xml". When running through npm, keep the separator before CLI flags: npm run dev -- --rss team-news.xml --include-ai-ml.

    The date range and --limit apply to the combined selection, not separately to each feed. Duplicate URLs ignore fragments, trailing slashes, and common tracking parameters; article-identifying query parameters are retained. RSS uses content:encoded or description; Atom supports published/updated dates, alternate links, content and summaries. Remote relative links use the feed URL; local feeds with relative links must provide xml:base.

    Use -H, --full-articles to fetch the linked page instead of embedded RSS/Atom text. The page must contain readable article or main content; extraction failures are reported, never silently replaced by a short excerpt. Without this flag, feed text supplies the content; pages may still be fetched for image discovery during enrichment.

    Replace the base source

    --feed replaces the base changelog with an RSS URL or local XML file. With no other source flags, only that feed is collected. You can combine it with --rss and --include-ai-ml to add sources explicitly. On resume, repeat the same source flags so the selected article URLs remain compatible with the checkpoint.

    Deterministic repository fixture
    npm run dev -- --from 2026-08-01 --to 2026-08-31 --feed test/fixtures/feed.xml --no-ai

    Guides / Selection

    Save settings. Preview before spending.

    -p, --profile loads a named profile from .copilot-changelog.json in the current directory. Use -g, --config for another file. No configuration file is loaded implicitly when neither option is supplied.

    Example .copilot-changelog.json
    {
  "version": 1,
  "defaults": { "model": "auto", "concurrency": 3, "maxCredits": "5" },
  "profiles": {
    "team": { "audience": "developer", "website": true, "rss": ["team-news.xml"] },
    "executive": { "audience": "executive", "evidence": true }
  }
}

    Precedence is explicit CLI options, then the named profile, then configuration defaults, then CLI defaults. Arrays supplied on the CLI replace profile arrays. Local feed, output, cache and state paths in profiles are relative to the configuration file. CLI paths remain relative to the working directory. Unknown settings, malformed values and missing profiles fail explicitly. Never store credentials in profiles.

    Profiles accept from, to, output, model, limit, feed, rss, includeAiMl, ai, website, concurrency, requestTimeout, slidesLanguage, speakerNotesLanguages, include, exclude, maxCredits, cache, cacheDir, stateDir, fullArticles, audience and evidence. Operational actions such as restart and import stay explicit CLI arguments.

    Preview the selection
    copilot-changelog --profile team --include agent editor --exclude retirement --dry-run
copilot-changelog --config examples/profiles.json --profile team --no-include-ai-ml --no-website --dry-run

    --include accepts titles containing any supplied literal substring, ignoring case. --exclude rejects titles containing any supplied substring and takes priority. Filters apply to titles, not downloaded article bodies, before the global limit. Repeated keywords and quoted phrases are supported.

    --dry-run prints JSON with titles, publication dates, source identities and selection reasons: selected, duplicate, include-filter, exclude-filter, limit or already-delivered. It makes no AI calls, downloads no article pages, writes no briefing/checkpoint/incremental files, and does not advance history. Remote feed/index metadata may be read from or written to the normal source cache. Out-of-range entries are filtered during discovery.

    The default standard audience preserves existing instructions. executive emphasizes decisions and source-backed business impact; developer emphasizes workflows and prerequisites; administrator emphasizes rollout, eligibility, controls and operations. Presets affect AI writing, not the source-based slide section. --no-ai remains a deterministic test mode.

    Guides / Output design

    Structured for the audience

    A deck contains an opening slide, section dividers, and a visual title plus a detail slide for each accepted article. Images preserve their aspect ratio. Source links, publication dates, the Copilot mark, and localized speaker notes keep the briefing grounded.

    Section-specific detail cards
    SectionWhen it appliesCards
    ModelsNewly available models, not settings, policies, pricing, or model pickers.Model name · Availability · Key capabilities · When to use / avoid
    Enterprise AdminsEnterprise owner/admin settings in the GitHub web portal or management console. Generic member features and API/CLI-only administration stay in their topic section.Announcement · Availability · Impact · Audience
    AnnouncementsBroader product, workflow, and adoption changes.Announcement · Availability · Impact · Audience
    IDEChanges in supported editors.Feature · Availability · Key capabilities · How to use
    RetirementsDeprecations, removals, and migrations.Subject · Retirement date · Reasons · Replacement

    Models, IDE, and Retirements use equal-width cards. Announcements and Enterprise Admins give the main explanation and impact cards a wider left column, with availability and audience on the right.

    Content budgets

    • Summary: one complete sentence, at most 32 words / 220 characters, leading with the product or capability.
    • Notes: 2–4 standalone bullets, each at most 16 words / 110 characters.
    • Explanatory cards: target 28–34 words; at most 36 words / 250 characters for capabilities, usage guidance, reasons, and replacement.
    • Wide announcement/impact cards: up to 44 words / 300 characters. Announcement prompts target 30–40 words.
    • Compact labels: up to 18 words / 130 characters. Availability, retirement date, and audience use up to 26 words / 170 characters.
    • Speaker notes: the prompt targets an 80–140 word presenter script for every requested language. This is a writing target, not a currently enforced word-count limit.

    Each card should contribute a distinct fact: a concrete change, mechanism, practical effect, action, or essential qualifier. Short sources are not padded with invented information. Up to three semicolon-separated points are allowed; commas inside model names or qualifiers do not count as separate points.

    Guides / AI quality

    Review that tells the model what failed

    The source determines the required section. Copilot receives the article and section-specific instructions, with examples encouraging concrete explanations rather than vague benefit statements.

    The initial prompt includes only the assigned section's guidance and lists the exact hard word/character limits used by the validator. Its structural template shows a valid bullet count, distinguishes mandatory limits from preferred writing targets, and asks the model to check its JSON, field limits, factual qualifiers and optional evidence/localization before sending the first response. Limits are shared with the validator in code to prevent drift.

    These instructions reduce avoidable ambiguity without weakening validation or discarding facts to fit. They do not guarantee a valid first answer, and a self-check instruction is not an additional verification call. Retry and final-review limits are unchanged. The trace records validation issues and attempts; use real run results to assess first-attempt acceptance rather than assuming a shorter prompt guarantees fewer calls.

    1. Generate and validate. The initial response is checked for structure, required fields, presentation limits, and requested notes.
    2. Correct with feedback. Up to three corrective rewrites receive the exact validation errors. Prompts preserve valid fields, exceptions, eligibility, deadlines, and prerequisites.
    3. Request a final review. After four invalid enrichment attempts, a separate tool-disabled reviewer receives the rejected response, validator errors, and original source-grounded task.
    4. Continue when content is still invalid. Omit the article's slides with a warning, process later articles, and keep accepted work in the checkpoint for resume.
    No mechanical trimming

    AI-generated fields are rewritten, not truncated, and extra bullets are not silently dropped. The model is asked to remove repetition before removing source-backed explanations.

    Transient SDK failures share the bounded attempt budget. The next prompt receives the latest request error, the original task, and any outstanding validation problems without nesting previous retry prompts. Error feedback can help with actionable response problems, but cannot repair authentication or service outages. Timeouts are not retried automatically. Empty primary or reviewer responses, service failures, and trace-write errors remain explicit failures rather than being treated as content-review rejections.

    These checks validate presentation content and formatting; they are not an independent factual audit. Review generated slides before sharing them with an audience.

    Guides / Editorial workflow

    Reuse, edit, and regenerate only what needs work

    Accepted-content reuse

    Accepted content is cached under output/.content-cache by source content, content version, requested model, AI mode, languages, audience and evidence settings. Date ranges and output formats are not part of the key. Cache hits require no new AI calls and incur no new AI credits in this briefing; source/image preparation may still perform network requests. Change --cache-dir to share a cache across output directories. --no-cache disables reads and writes; --restart bypasses reads to request fresh text. Corrupt entries are reported rather than silently regenerated at your expense.

    Review before rendering

    Create a draft, edit it, then render offline
    copilot-changelog --audience executive --speaker-notes-languages en,ja --evidence --max-credits 5 --review-only --export-json review.json
copilot-changelog --import-json review.json --website --export-json reviewed.json

    --export-json saves a versioned content document containing sources, accepted fields, settings, original date range, omitted URLs and reported usage. --review-only writes JSON instead of PowerPoint/HTML and keeps the checkpoint; without an explicit path it writes a date-named .review.json. Edit summaries, notes, details or presenter scripts without removing required keys.

    --import-json validates the document and renders it without fetching sources or calling AI. It uses the saved range and generation settings, so omit source/date overrides and incompatible generation overrides. Import cannot be combined with dry-run or incremental mode. Invalid fields, unsupported source URLs and invalid evidence fail before export. Ordinary import does not replace an existing run checkpoint. Accepted edits can enter the content cache for future reuse.

    Targeted regeneration

    Use an exact article URL from the exported JSON
    copilot-changelog --import-json reviewed.json --regenerate https://example.com/article --regenerate-field summary --export-json revised.json
copilot-changelog --import-json reviewed.json --regenerate https://example.com/article --regenerate-language ja --export-json revised.json
# Omit the field/language selectors to regenerate the complete selected article:
copilot-changelog --import-json reviewed.json --regenerate https://example.com/article --export-json revised.json

    Regeneration requires an AI-generated imported document. Only selected article URLs invoke AI. Select summary, notes, or details.KEY with --regenerate-field; select an existing presenter-script language with --regenerate-language. Both can be combined. Unselected articles and fields remain unchanged even if the model tries to rewrite them. Invalid field names, missing URLs and languages absent from the document are reported. A date-named .revised.json is written when no export path is given. Failed revisions keep their previous accepted content in the output and remain pending in the checkpoint.

    Evidence for human review

    --evidence requires at least one supporting quote for the summary, every note, every detail card and every requested presenter script. Quotes must occur verbatim in the source after whitespace normalization and link to the supplied article URL. Evidence is retained in JSON, PowerPoint speaker notes and expandable HTML panels. This checks quotation provenance, not whether each claim logically follows from the quote; human factual review is still necessary. Evidence generation requires AI, or previously accepted evidence when importing or reusing content.

    Guides / Files & diagnostics

    Know what gets written

    Example output directory
    output/
  copilot-changelog-2026-08-01-to-2026-08-31.pptx
  copilot-changelog-2026-08-01-to-2026-08-31.trace.jsonl
  copilot-changelog-2026-08-01-to-2026-08-31.html  # with --website

    Different date ranges have different filenames. Re-running the same range rewrites its deck and requested website; choose another --output directory to preserve an earlier version.

    The optional website embeds article images and provides local search. It is a generated digest, separate from this GitHub Pages documentation site. Slide and note languages are independently selectable; the digest's interface labels remain English.

    Open the completed deck

    After output writing, state cleanup and AI credit reporting, the final summary includes Open deck. Recognized hyperlink-capable terminals, including Windows Terminal and VS Code, receive a clickable terminal hyperlink; use the terminal's click or Ctrl+click gesture. Other terminals, redirected output, CI and NO_COLOR receive a fully encoded file:// URL that can be copied or opened by a terminal that detects file links. Paths containing spaces, Unicode, percent signs or # are encoded safely. No file is opened automatically.

    Partial decks still receive a link, followed by a visible reminder to re-run the same command with --resume. Keep the same dates, sources, model and locales, and remove --restart. A budget pause also reminds you to review its credit/usage warning before retrying. Imported partial JSON points you back to the original source-collection command; importing the same incomplete document cannot restore absent articles. Review-only mode links to the editable JSON instead of claiming a deck was generated; failed or dry-run commands do not show a completion link.

    Trace logs

    The JSONL trace is appended on each run with a unique runId. It records source preparation, prompts, raw AI responses, validation, checkpoint activity, skipped articles, and failures. Its path is printed at startup and included in error messages.

    Mirror trace events to stderr
    copilot-changelog --from 2026-08-01 --to 2026-08-31 --verbose
    Review logs before sharing

    Trace files and verbose terminal output include source excerpts, full prompts, and generated text. Without --verbose, the trace file is still written.

    AI credit totals

    AI runs print reported AI credits at the end, including handled failures. Usage includes primary calls, corrective retries, and the final reviewer, even for omitted articles. Live SDK billing events are persisted as requests run. Resume adds new usage to the checkpoint total and prints the current execution separately; restart starts a new total. Final totals remain in the trace after the checkpoint is removed.

    Credits use the SDK's copilotUsage.totalNanoAiu field divided by one billion, following the SDK usage guide. Premium-request multipliers are not treated as AI credits. If billing events are missing, a request is interrupted, or an older checkpoint has no usage history, the CLI reports a known lower bound or unavailable, not an exact zero. Usage not delivered or saved before forced termination cannot be reconstructed; this is reported runtime usage, not an account billing statement.

    Soft spending limits

    -b, --max-credits applies cumulatively to the briefing, including saved attempts on resume and usage recorded in an imported document. It accepts zero and up to nine decimal places. Before each primary, corrective or reviewer request, the CLI checks reported spend. Already-running concurrent requests can finish and exceed the limit: this is not a prepaid reservation or a hard billing cap.

    A budget pause preserves accepted content, writes available outputs and the checkpoint, and exits with code 2. Resume with a higher limit to continue. If billing reports or earlier usage are missing, budgeted generation pauses rather than guessing that calls were free. A zero budget can still reuse cached content or render imported content without AI. Unbudgeted behavior is unchanged.

    Guides / Recovery

    Continue, don't start over

    A hidden checkpoint is saved after each successfully enriched article. If a slide still fails review, later articles continue and the CLI writes a partial deck. The rejected article remains pending.

    Retry pending articles with the same configuration
    copilot-changelog --from 2026-08-01 --to 2026-08-31 --resume

    Resume reuses accepted articles, retries missing ones, and rewrites the deck with recovered slides. Add --website again if you also want to update the digest. The checkpoint is removed only after all selected articles complete and every requested output is written.

    Interactive versus automated runs

    An interactive terminal asks Previous run found (7/12 entries completed). Resume or restart? [R/s]:. Enter or R resumes; S discards the checkpoint. Scripts and CI must explicitly choose --resume or --restart.

    Discard progress and regenerate all selected content
    copilot-changelog --from 2026-08-01 --to 2026-08-31 --restart

    Compatibility and locks

    • Checkpoints match selected article URLs, model, AI mode, languages, audience, evidence requirements, regeneration target and content format version. An incompatible checkpoint is discarded with a message. Changed source content invalidates the affected accepted articles.
    • Changing concurrency or request timeout does not invalidate a compatible checkpoint. Layout changes can reuse accepted text; use restart to request new AI text.
    • Malformed checkpoints are preserved and reported on resume. Restart discards them without parsing.
    • A per-deck .lock blocks competing processes for the same output directory and date range. Restart does not override an active lock.

    Recover a stale run lock

    Use the exact lock-file path shown in the error
    copilot-changelog unlock "output/.copilot-changelog-2026-08-01-to-2026-08-31.lock"
copilot-changelog --from 2026-08-01 --to 2026-08-31 --resume

    unlock removes only one regular run-lock file whose recorded PID no longer exists on the current host. It supports briefing locks and incremental-state locks. It refuses active or protected processes, another host's locks, malformed ownership data, symbolic/hard links, directories and non-lock paths. There is no force option. Checkpoints and caches are never deleted.

    A temporary .recovery ownership file coordinates removal with new runs. If recovery itself was interrupted, the CLI reports that exact file; it can also be passed to unlock once its local owner is confirmed dead. Portable-updater lock directories have different recovery requirements and are deliberately excluded.

    After a forced termination

    Use the reported stale lock path and then resume. Do not delete the checkpoint or terminate other processes merely to bypass a lock. Normal completion and handled errors release run locks automatically; unknown ownership requires manual investigation.

    Reference / Runtime

    Predictable work, bounded waits

    Enrichment defaults to three concurrent article workers, using one shared client and one fresh session per article. Use --concurrency 1 for sequential processing or select another value from 1 through 8. Explicit CLI or profile settings override the default. The collector still uses five download slots independently. Corrective prompts stay associated with their source; results retain changelog order within each section.

    Interactive terminals show a WinGet-style block progress bar with percentage, processed/total article count, elapsed time and an animated wait indicator. A row per concurrent worker remains below it with the article title, attempt, validation and reviewer status. The display updates in place without appending a new bar for each refresh.

    Example while waiting for concurrent AI responses
    \ Enriching  ████████████▒▒▒▒▒▒▒▒▒▒▒▒  6/12 (50%) 00:42
Worker 1: attempt 1 - Agent workflow improvements
Worker 2: validating - Model availability update

    Percentage measures processed articles, including omissions listed separately, and starts from accepted articles on resume. It is not a guessed percentage of a model response: while an AI request is pending, the spinner and elapsed time move but the article count does not. The timer stops on completion, error, budget pause or display cleanup and cannot keep the CLI process alive. Each new phase starts its own elapsed-time counter.

    Rows retain severity colors and are fitted to terminal width before styling. Narrow terminals shorten the phase label and bar before dropping the elapsed time; counters remain visible where space permits. Unicode blocks use fractional fill; limited terminals (TERM=linux or a C/POSIX locale) fall back to ASCII. Warnings remain visible outside the live display.

    Redirected output and TERM=dumb use plain scrolling logs; --verbose disables in-place updates but keeps human-message colors in a capable terminal. CI does not schedule animated redraws. Verbose JSON trace lines are never colored or rewritten. NO_COLOR disables colors and styled hyperlinks without disabling the compact progress display. Increase terminal height to see every worker when space is limited.

    The 180-second deadline applies separately to each response, runtime startup, model discovery, and primary or reviewer session creation. Timeouts stop new articles and retries. Active peers may complete and be checkpointed before runtime shutdown.

    Resume with less contention
    copilot-changelog --from 2026-08-01 --to 2026-08-31 --resume --concurrency 1 --request-timeout 180

    Increasing the timeout permits slower responses; it does not speed up inference. Abort/disconnect and shutdown have bounded cleanup waits. Both sessions are cleaned up even if one cleanup fails, and cleanup diagnostics are reported alongside the original error. A forced SDK stop is attempted if graceful shutdown fails.

    Source downloads remain parallel. Help and version commands avoid loading generation dependencies, and the SDK is imported only when AI is needed. Sessions have no tools available because the source is supplied. PowerPoint theme changes happen in memory before the final write.

    Reference / Maintenance

    Keep the CLI current

    Check, then update
    copilot-changelog --version
copilot-changelog update --check
copilot-changelog update
# After the updater finishes:
copilot-changelog update --status

    Updates require a published GitHub release. Release lookup allows 30 seconds; each asset download allows five minutes. Downloaded release assets are verified against SHA256SUMS.

    • npm: installs the new version with npm install --global; that version must also be published to npm.
    • Windows setup: launches the new installer after the current process exits, targets the same installation directory and verifies its package version before logging success.
    • Debian / macOS packages: invoke sudo dpkg -i or sudo installer; administrator credentials may be required.
    • Portable: stages and replaces the managed application, runtime, launcher, and README after exit. Old dependency directories are not merged. The installed version is checked before committing; a mismatch or replacement failure rolls back managed files. User output outside managed paths is preserved.
    • Scoop / Homebrew: leave managed files untouched and print the owning manager's update command. Use scoop update copilot-changelog or brew update && brew upgrade copilot-changelog. These channels may lag behind GitHub while their update PR is reviewed.

    A source checkout is not an npm-global installation: running npm run dev -- update or node dist/cli.js update reports how to update and rebuild the checkout instead of installing a different copy and claiming success. Its development manifest can still say 0.0.1 while a released installer reports a tag-derived version such as 0.0.2.

    Close other running copies first. “Will be installed/applied after this process exits” means scheduled, not completed. The command prints the target directory and result-log path; use update --status after completion to read the recorded outcome and identify the exact copy being invoked. This diagnostic does not contact GitHub or install anything. Source checkouts and npm installs do not have a bundled updater-result log.

    If a terminal still shows an old version, open a new terminal and inspect command resolution. On PowerShell use Get-Command copilot-changelog -All. Compare its path with the updater's target and run that target explicitly. Checks consult published stable GitHub releases, not untagged commits on main. Competing portable updaters are blocked by .copilot-changelog-update.lock.

    Interrupted portable update

    Confirm that no updater is active. Inspect the logged backup location and restore retained managed files if needed before removing the stale update lock. Do not delete recovery backups blindly.

    Reference / Help

    When a run needs attention

    A slide was omitted after review

    The remaining accepted content is still written. Re-run the same dates, model, feed selection, and language settings with --resume. The rejected article is retried; accepted text is reused.

    Authentication, model, or request failure

    Verify Copilot access and authentication. Check the reported model availability, reduce concurrency to 1, and resume. Changing the model makes the existing checkpoint incompatible; keep it unchanged if you need to preserve completed AI work.

    Source preparation failed

    Every selected article must be readable before enrichment starts. Check the URL, feed content, and internet connection. Downloaded articles remain cached. If the diagnostic identifies an unreadable cache directory, repair its permissions or remove that specific cache after reviewing the error.

    A run lock or damaged checkpoint remains

    Use copilot-changelog unlock <path> for the reported stale local run-lock file. It refuses active and unknown owners and never deletes a checkpoint. A damaged checkpoint is preserved on resume; --restart discards it. Neither command bypasses an active run lock.

    The CLI is not found on Windows

    Open a new terminal after installing so the updated PATH is loaded. For a portable package, invoke the launcher from its extracted directory or add that directory to PATH.

    An option is unknown or does something unexpected

    Check copilot-changelog --version and copilot-changelog --help: an installed release may be older than this source guide. Short aliases remain case-sensitive and are listed in the reference table. Use long options in scripts, and keep -- between npm run dev and CLI arguments.

    Badges, documentation, or download links return 404

    The repository must be accessible and pushed, workflows must have run, and downloads require a release. Enable GitHub Pages with GitHub Actions as its source. See the publishing checklist; local files alone do not create a public site.

    Trace or output writing failed

    Check directory permissions, available disk space, and whether the presentation is open in another application. Fix the filesystem problem and resume. Do not share the trace without reviewing its prompts and source content.

    Build & publish / Automation

    Incremental briefings on your schedule

    Run only pending or newly discovered articles
    copilot-changelog --config examples/profiles.json --profile team --since-last-run --resume

    --since-last-run keeps durable history per profile/source/filter/generation selection under output/.briefing-state. The first run uses the requested dates; later runs continue from saved history, not a newly supplied start date. A pending failed run retains its exact time window. Use --resume for unattended checkpoint recovery.

    History advances only after every selected article is accepted and all requested outputs are written. Budget pauses, omitted content, source failures and review-only drafts do not advance it. Already-delivered URLs are excluded before the global limit; articles left behind by --limit remain eligible on later runs. The final day overlaps to avoid losing entries from date-only changelog indexes. This is not a monitor for arbitrarily backdated articles or revisions to already-delivered URLs.

    Source/filter or generation-setting changes create separate histories. Changing a limit, timeout or concurrency does not. Use --state-dir to choose durable storage or start a separate history. Incremental and per-deck locks prevent competing runs. Do not delete a lock until you have confirmed its owning process is no longer running.

    GitHub Actions template

    The repository includes examples/scheduled-briefing.yml and sample profiles. The YAML is outside the workflow directory, so it is not active. Review the profile and its five-credit soft budget, add a repository secret named COPILOT_TOKEN with Copilot Requests permission, then copy the template into .github/workflows/ only when you intend to enable it.

    The template runs weekly at 07:00 UTC on Monday or manually, prevents overlapping runs, restores accepted content and incremental state, and saves checkpoints even after budget pauses. Its cache is best-effort: GitHub may evict it. For guaranteed retention use durable storage on a persistent runner, or a Windows task with a backed-up state directory. Missing history starts a fresh selection and can incur repeat AI cost.

    Windows Task Scheduler template

    Review examples/windows-weekly-task.xml, replace the Node/repository paths and start time, then import it through Task Scheduler yourself. It uses the signed-in user's credentials, least privilege and IgnoreNew to avoid overlapping instances. Build the CLI and authenticate Copilot as that user first. No command in this project registers the task automatically.

    Persistent state contains source content

    Editable JSON, accepted-content caches and checkpoints can contain article text, generated content and images. Protect them like your source material. The example workflow uploads generated outputs, not trace logs; review repository access and artifact retention before enabling it. Do not store credentials in profiles or task XML.

    Build & publish / Automation

    From a tag to a release

    • ci.yml runs type-checks and tests on Windows, Linux, and macOS, including the minimum supported Node version.
    • pages.yml publishes this documentation independently of application releases.
    • release.yml validates the version, builds native platform packages, generates SHA256SUMS, and publishes only after validation succeeds.

    Commit the source you want to release, then tag that commit. The release tag supplies the version used in packaged manifests and lockfiles; the checked-in development version does not have to match. Tags must use vX.Y.Z, optionally with a SemVer prerelease suffix such as v0.0.3-rc.1. Build metadata suffixes are not accepted.

    Publish a new source revision
    git tag v0.0.3
git push origin v0.0.3

    The workflow resolves the tag to an exact commit, validates the version, then stamps package.json and package-lock.json in each isolated build/validation workspace before installing dependencies. It does not change the source tag or commit. All artifacts therefore contain the tagged source and the tag-derived version. Prerelease tags publish prereleases.

    Recover an existing failed tag using the updated workflow
    gh workflow run release.yml --ref main --field tag=v0.0.2

    First push the updated workflow to main. The optional tag dispatch input builds and publishes that existing tag; it does not move it. For v0.0.2, this means the original tagged source is packaged as version 0.0.2, not newer untagged source. Rerunning an old failed run still uses its old workflow. To ship newer source, create a new tag after committing it. An already-published GitHub release is not overwritten.

    Dispatch without a tag builds the selected branch using its manifest version without publishing. Successful stable releases call the distribution workflow directly after GitHub release creation. Prereleases are not submitted to package managers. Workflows use Node 24-compatible action releases and pin Linux x64 jobs to Ubuntu 24.04 instead of following ubuntu-latest across operating-system migrations.

    If a pull-request workflow has no jobs and reports that approval expired, approve a newly requested run in GitHub Actions. This is separate from a test or build failure.

    Build & publish / Package managers

    Publish once, distribute deliberately

    After a stable GitHub release is created, release.yml calls distribute.yml. The workflow prepares all four channels without requiring publication credentials. It downloads the version-specific installer and archives, verifies every SHA-256 against the released SHA256SUMS, and builds the npm tarball from the exact resolved tag commit, not from newer branch code.

    The workflow artifact distribution-vX.Y.Z contains three WinGet YAML manifests, a Scoop bucket manifest, a Homebrew formula covering macOS/Linux x64/ARM64, the npm tarball, and metadata with source commit, URLs and hashes. Artifacts are retained for 30 days; they are not automatically published to external registries. The preparation job verifies Homebrew syntax; actual registry validation and clean-machine installation tests are still required before first distribution.

    One-time repository configuration

    Set repository variables and secrets under Settings → Secrets and variables → Actions. A publication variable must equal the lowercase string true to enable its channel. Leave it unset to keep publication disabled. Enabling a channel without required configuration fails that job explicitly; the already-created GitHub release remains available.

    WinGet, Scoop and Homebrew setup

    Create and initialize the fork/bucket/tap repositories before enabling publication. Installer/archive URLs must be publicly downloadable without authentication. WinGet requires a genuine fork of microsoft/winget-pkgs; the default package identifier is a proposal, not an existing registration or a guarantee of acceptance. Confirm the identifier and installer metadata before the first submission. The current installer is per-user, x64, Inno Setup, with the stable application ID recorded in the generated manifest.

    Tokens must be able to read the target repository, write branches in the publication repository, and open pull requests. For your own Scoop/Homebrew repositories, a fine-grained token or GitHub App token with Contents and Pull requests read/write is suitable. WinGet cross-fork submission needs credentials permitted to create a fork branch and an upstream PR; a classic token with public_repo is one option. Use the narrowest workable permissions and never place tokens in manifests or command-line arguments.

    The workflow opens reviewable PRs, not automatic merges. For first WinGet submission, validate the generated manifests and test install, upgrade, uninstall and PATH behavior in a clean Windows environment. WinGet community checks and approval determine availability. Scoop/Homebrew users must add your bucket/tap after you merge its initial package PR. These are personal repositories, not automatic submissions to Scoop Main or Homebrew Core.

    npm trusted publishing

    Ensure you own the copilot-changelog-cli npm package. If it does not yet exist, bootstrap its first publication manually from a reviewed package; then configure trusted publishers in its npm package settings. Match this GitHub owner/repository exactly. The automatic reusable-workflow route validates the calling workflow filename, so configure release.yml; add a second trusted publisher for distribute.yml if you want manual retry publication.

    The npm job uses GitHub-hosted runners, id-token: write in the caller and publisher, and npm 11.5.1 or later. Newly configured npm trust must be used before its configuration expires; consult npm's trusted publishing guide. The package repository URL must match the publishing repository. The prepared tarball is published with scripts disabled; no packaging lifecycle runs with publication credentials.

    For accurate npm provenance, the workflow commit must equal the packaged release commit. Normal tag-triggered releases satisfy this. A manual retry for npm should use --ref vX.Y.Z when that tag already contains the distribution workflow. Recovery from main can prepare older tags and submit registry PRs, but npm publication stops if the commits differ rather than attributing an old package to new source. Publish a new tag to distribute updated source through all channels.

    Retry after configuration or review

    Distribute an already-published stable release whose tag includes this workflow
    gh workflow run distribute.yml --ref v0.0.3 --field tag=v0.0.3
# Manifest-only recovery using newer tooling:
gh workflow run distribute.yml --ref main --field tag=v0.0.3

    Use a real published stable tag after pushing these workflows to the selected branch. Manual distribution does not create or replace the GitHub release. Drafts, prereleases, missing assets and moved tags relative to the calling release's recorded commit are rejected. An identical open registry PR is reused; a conflicting branch, closed PR or conflicting published WinGet version fails for manual review. npm retries skip an already-published version only when its integrity exactly matches the prepared tarball.

    Published versions are immutable

    Never replace release binaries after checksums or registry manifests are published. Create a new version instead. A post-release distribution failure does not delete the release and does not imply that all enabled channels failed; inspect each job before retrying. This project does not create forks, buckets, taps, npm accounts or trusted-publisher registrations automatically.
